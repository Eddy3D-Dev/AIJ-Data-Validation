# API

A **static** API: every endpoint is a file under `/api/` on this site, generated by `scripts/build_api.py` from the
cleaned data and served by GitHub Pages. Plain HTTP GET, no keys, CORS-open (`Access-Control-Allow-Origin: *`).

- Base URL, always the newest release: `https://sustainableurbansystems.com/CFD-Test-Cases-Architectural-Institute-of-Japan-AIJ/api`
- One release, frozen: `https://sustainableurbansystems.com/CFD-Test-Cases-Architectural-Institute-of-Japan-AIJ/api/<release>`, for
  example `.../api/3.0.0`. The files and paths are the same; see [Versions and pinning](#versions-and-pinning).
- Fallback, the same files raw from the repository: `https://raw.githubusercontent.com/SustainableUrbanSystemsLab/CFD-Test-Cases-Architectural-Institute-of-Japan-AIJ/main/docs/api`
- Machine-readable: [`/api/openapi.json`]({{ '/api/openapi.json' | relative_url }}) (OpenAPI 3.1), a JSON Schema for every
  document under [`/api/schemas/`]({{ '/api/schemas/case.schema.json' | relative_url }}), and the agent entry point
  [`/llms.txt`]({{ '/llms.txt' | relative_url }}).

## Versions and pinning

Every release of the data and API is kept as a frozen copy of the whole API under `/api/<release>/`. The unversioned
`/api/` paths serve the newest release, and `versions.json` lists them all:

| Address | What it serves | When it changes |
|---|---|---|
| `/api/versions.json` | every release, newest first: version, date, status, `schema_version`, `data_version`, `base_url`, tag, changelog | with each release |
| `/api/<release>/...`, for example `/api/3.0.0/index.json` | exactly the files of that release | never, once the release is tagged |
| `/api/...`, for example `/api/index.json` | the newest release (the **latest alias**) | with each release |

A release's copy and the alias hold the same files at the same relative paths. They differ only in the address a
document gives its own files. Inside a release's copy every URL to a file of the API points back into the same copy:
`index.json` says `"tree": "release"` and its `base_url` ends in the release number, and the `$schema` URL of every
document, the `?v=` download URLs, the `servers` of `openapi.json` and the endpoint URLs in `llms.txt` all start with
that `base_url`. The one file outside it is `versions.json` (`versions_url` in `index.json`), which has a single home at
the unversioned path because it changes with every release. A client that starts in a copy never leaves it for data. The alias says `"tree": "latest"` and names the copy it currently
equals in `release_base_url`.

**To pin a script to a release, use that release's base URL and change nothing else.**

```bash
LIVE=https://sustainableurbansystems.com/CFD-Test-Cases-Architectural-Institute-of-Japan-AIJ/api
BASE=$LIVE/3.0.0            # pinned to release 3.0.0; $LIVE alone follows the newest release

curl -s -A "aij-client/1.0" $BASE/index.json | jq '.versions'          # release 3.0.0, whatever is newer
curl -s -A "aij-client/1.0" $BASE/cases/B.json | jq '.points.csv.url'  # .../api/3.0.0/cases/B/points.csv?v=...
```

**To find the releases, and to learn the base URL of one,** `GET /api/versions.json`:

```bash
curl -s -A "aij-client/1.0" $LIVE/versions.json | jq -r '.versions[] | "\(.version) \(.status) \(.base_url)"'
```

Each entry of `versions` has:

| Field | Meaning |
|---|---|
| `version`, `date` | the release (the repository's `VERSION`, tag `vX.Y.Z`) and its date in `CHANGELOG.md` |
| `status` | `latest` for the newest release, `superseded` for every older one |
| `schema_version`, `data_version` | the JSON contract and the data fingerprint of that release |
| `base_url`, `index_url` | where that release's files are frozen, and its `index.json`. Fetch `base_url` + a path from `index.json` |
| `fallback_base_url` | the same files raw from the repository at the release tag, or `null` |
| `self_contained` | `true` if every API URL inside that release's documents points back into its `base_url`; if `false`, build URLs from `base_url` and a `path` in its `index.json` instead of following the links |
| `tag`, `tag_url`, `changelog_url` | the git tag, the GitHub release page and the changelog at that tag |

An address that names a base is one of four, depending on whether it is pinned and where it is served:

| | On this site | Raw from the repository |
|---|---|---|
| **Pinned** (never changes) | `release_base_url`; `base_url` inside a release's copy | `release.base_url`; `fallback_base_url` inside a release's copy |
| **Latest** | `base_url` in the alias | `fallback_base_url` in the alias |

Two limits. First, release 2.0.0 predates the layout and was not regenerated. Its copy `/api/2.0.0/` is the files of
tag `v2.0.0` byte for byte, except that each file's own addresses are rewritten into the copy (and the sizes and
hashes that `index.json` lists for the files that changed). `scripts/host_release.py` derives it from the tag, and
`scripts/release.py check` derives it again and compares every byte. The raw files at the tag are the originals
(`release.base_url` in that copy's `index.json`). Second, a release's copy freezes the API's files, not everything a
document links to: the figures and geometry renders under `/assets/` and the repository links (`source_url`,
`files_in_repository`, which point at `main`) are not part of the copy and can change later.

## Conventions

**Every JSON document starts with the same four keys.**

| Key | Meaning |
|---|---|
| `$schema` | the URL of the document's JSON Schema (draft 2020-12). The build validates every document against it. |
| `schema_version` | the version of this JSON contract, semantic versioning (see [Versioning](#versioning-and-changes)). The release of the data is `versions.release` in `index.json`. |
| `data_version` | a SHA-256 over every served measurement, geometry and score file. It changes when, and only when, the data changes. Quote it with any number you take from here. |
| `license` | `CC-BY-4.0`, the SPDX identifier. The data belongs to its collectors; cite them (see *Cite* on the home page). |

**Downloads are objects, not bare URLs.** Wherever a document points at a CSV, STL or ZIP file, it gives:

```json
{"url": ".../api/cases/B/points.csv?v=e8214b704821", "path": "cases/B/points.csv",
 "media_type": "text/csv", "bytes": 19396, "sha256": "e8214b7048218de9..."}
```

The `?v=` query is the first 12 hex digits of the file's SHA-256. The server ignores it, but a changed file gets a
new URL, so no cache can serve a stale copy. GitHub Pages caches CSV and ZIP files for 186 days. Use the URLs the
documents give, and check what you download against `sha256`. `index.json` lists every file in the API this way.

**Units and frames.** SI throughout: m, m/s, m²/s². Each case has one frame, and its `points.json` and STL files
share it. A–D are model-scale metres with +x along the wind at WD = 0. E is full-scale metres with +x east, +y north,
and meteorological wind directions. Read `frame`, `units` and `known_issues` in `cases/{id}.json` before using any
number.

**Templated endpoints.** Paths such as `cases/{id}.json` and `schemas/{name}.schema.json` are templates, not
URLs to fetch. In `index.json` such an endpoint says `templated: true` and lists every concrete file under
`urls`, for example `.../api/schemas/case.schema.json`. A single-file endpoint carries one `url`.

**Errors.** A path that does not exist returns HTTP 404 with GitHub Pages' HTML page, not JSON. Case ids are
`A`–`E`. The other path parameters are enumerated in `openapi.json`.

**Clients.** The custom domain is served through Cloudflare, which rejects some clients with HTTP 403. These
include Python's `urllib` with its default User-Agent and some AI crawlers; `curl`, `wget`, `requests`, `httpx` and
browsers are accepted. Send a descriptive `User-Agent` header, as the examples below do, or use the fallback base URL:
it serves byte-identical files (the same `sha256`) straight from the repository.

**STL content type.** GitHub Pages labels `.stl` responses `application/vnd.ms-pki.stl`, which is a Windows
certificate type. The body is ASCII STL regardless; read it as such.

## Endpoints

| Endpoint | What it returns |
|---|---|
| [`GET /api/index.json`]({{ '/api/index.json' | relative_url }}) | every endpoint and every file with its size and SHA-256; versions, compatibility policy, changelog, licence, citation |
| [`GET /api/versions.json`]({{ '/api/versions.json' | relative_url }}) | every release, newest first, with the `base_url` of its frozen copy (served only at this path; see [Versions and pinning](#versions-and-pinning)) |
| [`GET /api/cases.json`]({{ '/api/cases.json' | relative_url }}) | the five cases: id, title, frame, units, counts, engine status, links |
| `GET /api/cases/{id}.json` | one case in full: configurations (Case C's 9, Case E's before/after), frame, units, inflow fit and approach-flow profile, point-table summary, geometry files, validation status, `known_issues`, attribution |
| `GET /api/cases/{id}/points.json` | the cleaned measurement table: SI units, one frame, `null` where not measured; `columns` and `column_meaning` define each field |
| `GET /api/cases/{id}/points.csv` | the same table as CSV (an empty cell is `null`) |
| `GET /api/cases/{id}/approach_flow.csv` | the measured approach-flow profile: `z` (m), `U` (m/s), and `k` (m²/s²) or `u_rms` (m/s) where published |
| `GET /api/cases/{id}/geometry.json` | the case's STL files with statistics (triangles, bounding box, edge-manifold census), renders and captions, and the **box list** where the geometry is boxes (A–D) |
| `GET /api/cases/{id}/geometry.stl` | cleaned ASCII STL of the default configuration: metres, case frame, outward normals |
| `GET /api/cases/{id}/geometry_{configuration}.stl` | the other configurations: `C/geometry_0D.stl` and `C/geometry_1D.stl` (`geometry.stl` is 2D); `E/geometry_bc.stl`, before construction (`geometry.stl` is after construction) |
| `GET /api/cases/{id}/validation.json` | Eddy3D's scores per engine and run. Each result carries every score, the `headline` scores to quote, captioned figures, the reproducing fixture, and `pairs` |
| `GET /api/cases/{id}/pairs/{engine}.csv` | the measured and modelled value at every scored point of one engine's runs, so any score can be recomputed; each result's `pairs_columns` defines the columns |
| [`GET /api/validation.json`]({{ '/api/validation.json' | relative_url }}) | every case and engine in one table: status, runs, and each run's headline R, FAC2, FB and hit rate |
| [`GET /api/geometry.json`]({{ '/api/geometry.json' | relative_url }}) | every STL of every case in one list: case, configuration, units, frame, bounding box, size, SHA-256 |
| [`GET /api/geometry.zip`]({{ '/api/geometry.zip' | relative_url }}) | every STL in one archive. Each file keeps its own case's frame and units, so they are deliberately not one scene: overlaid they would stack at the origin, E is full scale while A–D are model scale, and C's three centre blocks and E's two states are alternatives, not neighbours |
| `GET /api/schemas/{name}.schema.json` | the JSON Schema of each document: `index`, `versions`, `cases`, `case`, `points`, `geometry`, `validation`, `validation-summary`, `geometry-index` |
| [`GET /api/openapi.json`]({{ '/api/openapi.json' | relative_url }}) | OpenAPI 3.1 description of every endpoint, with the schemas embedded |
| [`GET /api/llms.txt`]({{ '/api/llms.txt' | relative_url }}) | plain-text entry point for agents (also at [`/llms.txt`]({{ '/llms.txt' | relative_url }})) |

An engine's status for a case is `scored` (a run exists and its scores are served; whether it agrees is in the
numbers), `running`, `pending`, or `not comparable`: it cannot produce the measured quantity at the measured
location. For OpenLB that is at the resolution this hardware runs; for FluidX3D it is without a ground wall
function. The measurements behind both are on the [Validation]({{ '/validation/' | relative_url }}) page.
An engine that is not `scored` has no result for that case.

## Examples

### curl

```bash
BASE=https://sustainableurbansystems.com/CFD-Test-Cases-Architectural-Institute-of-Japan-AIJ/api   # newest release; append /3.0.0 to pin

curl -s $BASE/index.json | jq '.versions, (.endpoints[].path)'
curl -s $BASE/cases.json | jq '.cases[] | {id, title, counts, engines}'
curl -s $BASE/cases/B.json | jq '{frame, units, known_issues}'
curl -s $BASE/validation.json | jq '.cases[] | {case, engines: [.engines[] | {engine, status}]}'

# Downloads: take the URL from the document, then check the SHA-256.
url=$(curl -s $BASE/cases/B.json | jq -r '.points.csv.url')
sha=$(curl -s $BASE/cases/B.json | jq -r '.points.csv.sha256')
curl -s -o caseB.csv "$url" && echo "$sha  caseB.csv" | sha256sum -c -

curl -s $BASE/cases/D/geometry.json | jq '.files[0].boxes | length'      # 83
curl -s $BASE/cases/C/validation.json | jq '.results[] | {run_id, headline}'
curl -s -o aij_geometry.zip "$(curl -s $BASE/geometry.json | jq -r '.archive.url')"
```

### Python

Standard library only. This script runs as written against the live API.

```python
import csv, hashlib, io, json, statistics, urllib.request

# The newest release. To pin the analysis to one release, append its number (any in /api/versions.json): ".../api/3.0.0".
BASE = "https://sustainableurbansystems.com/CFD-Test-Cases-Architectural-Institute-of-Japan-AIJ/api"


def fetch(url):
    # A descriptive User-Agent: the site's CDN rejects urllib's default one (see Clients above).
    req = urllib.request.Request(url, headers={"User-Agent": "aij-uwe-example/1.0"})
    with urllib.request.urlopen(req) as r:
        return r.read()


def get_json(path):
    return json.loads(fetch(f"{BASE}/{path}"))


def download(d):
    """Fetch a download object and check it arrived intact."""
    body = fetch(d["url"])
    assert hashlib.sha256(body).hexdigest() == d["sha256"], f"{d['path']} is corrupt or stale"
    return body


index = get_json("index.json")
print(index["versions"])                              # API version, data version (a SHA-256 of the data)

case = get_json("cases/B.json")
print(case["frame"]["x"])                             # read the frame and the known issues BEFORE the numbers
print(case["known_issues"][0][:80])

pts = get_json("cases/B/points.json")
U_H = case["configuration"]["U_H_m_s"]
centre = [p for p in pts["points"] if abs(p["y"]) < 1e-9 and p["U"] is not None]
print(len(centre), "centre-plane points; U/U_H at the first:", round(centre[0]["U"] / U_H, 3))

rows = list(csv.DictReader(io.StringIO(download(case["points"]["csv"]).decode())))
print(len(rows), "rows in points.csv; columns", list(rows[0]))

geom = get_json("cases/D/geometry.json")
print(len(geom["files"][0]["boxes"]), "boxes in Case D")       # boxes where the geometry is boxes: no STL parsing
stl = download(geom["files"][0])                                # ...or the STL itself, checked against its SHA-256

summary = get_json("validation.json")                           # every case and engine in one table
for c in summary["cases"]:
    print(c["case"], {e["engine"]: e["status"] for e in c["engines"]})

# Recompute a published score from the per-point pairs behind it.
val = get_json("cases/A/validation.json")
run = next(r for r in val["results"] if r["run_id"] == "A.openfoam12-realizableKE")
pairs = list(csv.DictReader(io.StringIO(download(run["pairs"]).decode())))
R = statistics.correlation([float(p["U_meas"]) for p in pairs], [float(p["U_model"]) for p in pairs])
print("R of U/U_H recomputed:", round(R, 4), "published:", round(run["scores"]["velocity.U"]["R"], 4))
```

The last line prints `R of U/U_H recomputed: 0.9548 published: 0.9548`.

### Geometry conventions

- Metres. A–D are model scale, the scale the tunnel measured at. E is full scale, the scale of its 3dm and
  workbook. `units` in `geometry.json` states which.
- The origin is the building centre (A, B) or the array centre (C, D) on the ground plane. For E it is the centre
  of the reproduced area.
- +x runs along the wind at WD = 0 for A–D. E keeps its geographic frame (+x east, +y north), and its directions
  are meteorological: the direction the wind comes **from**, N = 0°, clockwise.
- Outward normals, LF line endings, one `solid` per file. A–D are watertight; E's buildings touch, so its shells
  share edges and are not.
- The build checks every STL: triangle count, edge-manifold census, and the bounding box against the stated
  dimensions. `validation/render_geometry.py` draws each one from the same code that writes it, and those are the
  renders on the case pages.

## Versioning and changes

Two semantic versions and one fingerprint, all in `index.json` under `versions`:

| | what it versions | moves when |
|---|---|---|
| `versions.release` | what is served: the API files and the cleaned tables, as one release (the repository's `VERSION`, tag `vX.Y.Z`) | MAJOR: a file, field or column renamed or removed, a CSV column added or reordered, a unit or frame changed; MINOR: something added; PATCH: a value or text corrected |
| `schema_version` (also `versions.schema`) | the JSON contract of these documents | MAJOR: a field renamed or removed; MINOR: a field or endpoint added; the changelog below |
| `data_version` (also `versions.data`) | nothing: it is the SHA-256 of the served data, a fingerprint | whenever a served measurement, geometry or score file changes |

`release` in `index.json` gives the release's date, tag, release page, changelog and `base_url`: the raw files of
that release's frozen copy at its tag, which never change. `release_base_url` is the same copy on this site, and
`versions.json` lists every release. To pin an analysis to one release, fetch from one of them (see
[Versions and pinning](#versions-and-pinning)):

```bash
REL=$(curl -s -A "aij-client/1.0" $BASE/index.json | jq -r .release_base_url)   # .../api/3.0.0
curl -s -A "aij-client/1.0" "$REL/cases/A/points.csv" | head -3
```

Within a major `schema_version` the API only adds: new fields, new endpoints, new runs. Clients must ignore
fields they do not know. A field is renamed or removed only in a new major version, listed below. `index.json`
serves the same changelog as `changelog`; the releases are in [`CHANGELOG.md`](https://github.com/SustainableUrbanSystemsLab/CFD-Test-Cases-Architectural-Institute-of-Japan-AIJ/blob/main/CHANGELOG.md).

## Regenerating and checking

```bash
# everything (cleaned tables, figures, API), in the pinned image: what CI runs
docker run --rm -v "$PWD:/w" -w /w "$(cat scripts/BUILD_IMAGE)" bash scripts/build_all.sh

# the API alone
pip install --require-hashes -r requirements.lock
python scripts/build_api.py          # builds docs/api/<VERSION>/ and docs/api/, the case pages and the site includes, then verifies
python scripts/build_api.py --check  # verify only
```

The build writes the frozen copy of the release in `VERSION` (`docs/api/<VERSION>/`) and then the latest alias
(`docs/api/`), from the same code, and writes `docs/api/versions.json`. It never touches another release's copy:
once a release is tagged, `python scripts/release.py check` fails if its copy differs from the tag. A new release
therefore adds one directory to `docs/api/` and moves the alias. Release 2.0.0 is not regenerated.

The build is a pure function of the repository: no timestamps and no commit hashes, so rebuilding unchanged inputs
gives byte-identical files. On every push and pull request, CI rebuilds everything in Python 3.12.12 (an image
pinned by digest) with every package pinned by hash, and fails if anything differs from what is committed or if
served content changed without the release version moving. The site deploys only after that check passes, and a
new `VERSION` is then tagged and released. Verification covers:

- every document against its JSON Schema, and `openapi.json` against the OpenAPI 3.1 specification;
- every file's size and SHA-256 against `index.json`, and every file served against the files listed, so a stray or
  missing file in any tree fails;
- every link inside every document, including that each `?v=` matches the file it points at, and that a link in a
  release's copy never leaves the copy (`versions.json` is the one file outside it);
- that the alias is the newest release, file for file: data files byte for byte, documents once their own address is
  accounted for;
- `versions.json` against a rebuild of it from the trees on disk and `CHANGELOG.md`;
- the point counts, the STL triangle counts and the archive's contents.

The point tables come from `clean/` (`points_source` in each `points.json` says which file). The scores and pairs
come from the snapshots in `validation/results/`, each registered in `RUNS` in `scripts/build_api.py`; an
unregistered snapshot stops the build.
